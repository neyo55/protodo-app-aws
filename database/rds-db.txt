You are asking the exact right question. In a production environment, you should never have to "hope" that your data is safe—you should **prove it**.

There are two ways we can confirm your data is permanently locked into your Amazon RDS PostgreSQL database and safely decoupled from the EC2 instance. We can either look directly inside the database, or we can run the ultimate "Chaos Test."

Here is how to do both.

### 🕵️‍♂️ Option 1: Look Directly Inside the Database (The Developer Way)

Since we installed the PostgreSQL client (`psql`) on your EC2 server in our `script.sh`, you can connect to your RDS database directly from the EC2 terminal and run SQL commands to see your users!

**Step 1:** SSH into your current running EC2 instance.
**Step 2:** Run this command to extract your database URL from the `.env` file and securely log into the RDS database:

```bash
DB_URL=$(grep DATABASE_URL /home/ubuntu/protodo-app/.env | cut -d '=' -f2-)
psql $DB_URL

```

**Step 3:** Once your terminal prompt changes to `=>` (which means you are inside the database), run these SQL commands:

```sql
-- See all the tables in your database
\dt

-- View the emails and names of everyone who has signed up
SELECT id, email, name FROM "user";

```

If you see the account you just created in that list, **your data is 100% safe in AWS RDS.** (Type `\q` and press Enter to exit the database).

### 🔥 Option 2: The Chaos Test (The DevOps Way)

Looking at the database is great, but the true test of a Highly Available (HA) architecture is destroying a server and watching the system heal itself without losing a single byte of user data.

Let's prove your architecture is indestructible:

1. Go to your **AWS Console > EC2 > Instances**.
2. Select your running `ProTodo-Worker` instance.
3. Click **Instance state > Terminate instance**.
4. **Do not touch anything else.**

**Watch the magic happen:**

* The Load Balancer will temporarily throw a 502 error because the server is dead.
* The Auto Scaling Group will detect the missing server, spin up a brand new one, run the `script.sh`, install Docker, fetch your AWS Parameter Store secrets, and launch the app.
* Within 3 to 5 minutes, your Target Group will turn **Green/Healthy**.
* Go to `https://app.neyothetechguy.com.ng/login` and type in the exact same email and password you just created.

If you successfully log in, you have definitively proven that your EC2 instances are completely stateless and your data is permanently safe in RDS!
